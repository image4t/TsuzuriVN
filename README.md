# 綴り — TsuzuriVN

Windows向けのビジュアルノベル制作・再生アプリです。Electron + React + TypeScript + Viteで実装しています。作品、画像、音声、原稿の下書きはPC上のフォルダに保存します。IndexedDBや外部サービスは使いません。

## インストールして使う

`release/TsuzuriVN-Setup-1.0.0.exe`を実行し、インストール先を選んでください。インストール後はスタートメニューまたはデスクトップのTsuzuriVNから起動します。Node.jsやViteサーバーの手動起動は不要です。インストーラーは現時点では未署名です。更新・アンインストール時も`UserData`やユーザーが作成したフォルダを残す削除フックを設定しています。

インストールせずに確認する場合は、`release/win-unpacked`全体を保持したまま`TsuzuriVN.exe`を実行してください。exeだけを別の場所にコピーすると起動できません。

## 開発環境

Node.js 22.12以上（推奨24）とnpmを使用します。

```sh
npm install
npm run dev
```

`npm run dev`はRendererとElectron Main/Preloadをビルドしてアプリを起動します。HTTPサーバーは起動しません。Windowsの`start.bat`も同じ処理です。コード変更後は再起動してください。

```sh
npm run build     # 型チェック、Renderer、Main、Preloadのビルド
npm start         # 既にビルドしたデスクトップアプリを起動
npm run pack:win  # Windows x64実行フォルダ release/win-unpacked
npm run dist:win  # Windows x64 NSISインストーラー
npm test          # モデル・ZIP・ファイル保存の単体/結合テスト
npm run test:desktop # Electron画面で保存・終了・再起動を検証
```

ビルド初回はElectronやNSISのダウンロードが必要です。通常利用ではネットワーク接続は不要です。`ELECTRON_RUN_AS_NODE`が設定された開発環境でも起動スクリプトはその変数を子プロセスから除外します。

## 保存先と作品の管理

初期の保存先は、インストール先フォルダ内の`UserData`です（`<インストール先>/UserData`）。開発起動ではリポジトリ内の`UserData`を使います。各作品の中に画像・音声・下書きをまとめて保存します。

- トップ画面・編集画面の上部の歯車「設定」から、テーマとプロジェクト・リソース共通の保存先を変更できます。「既定に戻す」でインストール先の`UserData`に戻せます。変更は新規作品へ適用し、既存作品は自動移動しません。
- 以前の既定保存先`Documents/TsuzuriVN`の作品と最近使った作品は引き続き一覧から開けます。個別に設定した別の保存先は維持します。
- インストール先が書き込み不可の場合も設定画面を開き、書き込み可能なフォルダへ変更できます。
- 「新規シナリオ」で作品ごとの独立したフォルダを作ります。
- 「作品フォルダを開く」で、既存の`scenario.json`があるフォルダを登録できます。作品を移動・コピーした場合もここから開き直せます。
- 一覧から編集、タイトル変更、複製、削除ができます。複製はMain Processで素材ファイルもコピーし、独立した作品にします。
- 削除は作品フォルダを同じ親フォルダの`.trash`へ移動する方式です。完全削除はしません。戻す場合はアプリを閉じてフォルダを取り出し、「作品フォルダを開く」で登録します。

作品フォルダの例:

```text
作品名_作品ID/
  scenario.json          # シーン、本文、話者、設定、素材一覧
  scenario.json.bak      # 直前の正常な保存
  assets/
    <sha256>.png         # 画像のバイナリ
    <sha256>.mp3         # 音声のバイナリ
  drafts/
    bulk.json            # 一括作成の原稿・話者割り当て
    bulk.json.bak
  backups/
    <日時_識別子>/       # 手動バックアップの独立した作品フォルダ
      scenario.json
      assets/
      drafts/
```

`scenario.json`は`format: "tsuzuri-folder"`、`version: 1`のフォルダ形式です。`project`内のシーンは従来のモデルを保ち、素材参照は`asset:<SHA-256>`です。`assets`一覧が各IDを`assets/<SHA-256>.<拡張子>`へ対応づけます。絶対パスや元素材のフルパスは作品に保存しません。

作品保存先の`UserData`と、アプリ設定の保存先は別です。アプリ設定はElectronの`app.getPath('userData')`配下の`settings.json`へ保存します。通常は`%APPDATA%/TsuzuriVN`配下です。既定の保存先、テーマ、最近使った作品のフォルダを管理します。設定ファイルを他のPCへコピーしなくても、作品フォルダ単独で開けます。

## 保存・バックアップ・復旧

編集内容は350ms後に自動保存されます。「未保存」「保存中…」「自動保存済み」「保存失敗」を表示します。Rendererの保存要求とMainのファイル書き込みを直列化し、先の保存処理が後の内容を上書きしないようにしています。

- 「保存・再試行」で即座に保存します。失敗した理由は画面に表示されます。
- 「保存先を開く」でエクスプローラーを開きます。
- 「バックアップ」は保存を完了してから素材・下書きを含むコピーを`backups`へ作成します。
- 「直前の保存に復旧」で確認後に`scenario.json.bak`へ戻せます。
- `scenario.json`が壊れた場合、正常な`.bak`があれば警告を表示して開きます。編集後の保存または手動保存で復旧できます。
- 過去の手動バックアップは、そのバックアップフォルダを別の場所へコピーし、「作品フォルダを開く」で開いてください。
- 保存先への書き込み権限、空き容量、ドライブ接続を確認してください。閉じる操作は本文・下書きの保存完了を待ちます。保存できなければ、編集を続けるか保存せず終了するか確認します。

保存は一時ファイルへ書き込み、fsync、JSONの再読み込み・検証を行ってから置換します。置換前に直前の正常なJSONを`.bak`へ保存します。異常終了時の未完了`.tmp`は作品として読み込みません。突然の停電・ドライブ故障に対して全データの永続性を保証するものではないため、別ドライブへのバックアップも推奨します。

復旧用の以前の保存やバックアップを壊さないため、未使用になった素材を自動削除しません。作品フォルダを移動するときはアプリを閉じ、フォルダ全体を移動してください。複数プロセスで同じ作品を同時編集する用途は対象外です。

## 旧ブラウザ版からの移行

1. **旧ブラウザ版を、従来使っていたブラウザ・URL・ポートで開きます。** IndexedDBの内容を新しいElectronアプリから直接参照することはできません。
2. 各作品を開き、「ZIP保存」で`.vn.zip`を書き出します。従来の素材埋め込みJSONも利用できます。
3. 新アプリの「ZIPを読み込む」または「JSONを読み込む」でそのファイルを選びます。
4. 新しい作品ID・作品フォルダを作成し、素材をバイナリへ変換して登録します。既存作品は上書きしません。正常な既存シーンIDは維持し、重複したシーンIDはエラーにします。
5. 本文・背景・音声の表示と再生を確認してから旧版のデータを整理してください。移行元ファイルは変更しません。

ZIPは従来の`tsuzuri-project`、version 2を維持し、旧ブラウザ版で書き出したZIPを読めます。「ZIP保存」は作品の受け渡しに、「JSON書き出し」は素材をData URLへ埋め込む旧形式との互換用に使います。ファイル保存はOSの保存ダイアログで場所を指定します。フォルダ形式の`scenario.json`自体は、互換JSONのインポートではなく「作品フォルダを開く」で開いてください。

旧版を起動する必要がある場合は、移行前のGitコミットを**別のチェックアウト**で起動してください。旧ブラウザ版のIndexedDBを消す処理は新アプリに含みません。

## シナリオ編集と再生

- シーンを追加・複製・削除し、ドラッグまたは上下ボタンで並べ替えます。本文は日本語の複数行、話者は任意です。本文欄の「コピー」で本文全体をコピーできます。
- 背景画像は既定で前のシーンを引き継ぎます。シーンごとに変更・画像なしを選べます。PNG / JPEG / WebP / GIF / AVIF、1素材25MBまで対応します。ファイル選択と背景へのドラッグ＆ドロップが使えます。
- ボイスはWAV / MP3を複数指定し、シーン開始時に順番に再生します。ファイル選択、ドラッグ＆ドロップ、または「フルパスを指定して追加」で登録します。フルパスは1行に1ファイル、引用符付きのWindowsパスも受け付けます。
- BGMはループ再生し、変更・停止するまで引き継ぎます。ボイスとBGMの音量は別に調整できます。
- 「文章からまとめて作成」で原稿の各行に話者を指定し、連続する同じ話者の行をまとめてシーンへ変換できます。原稿と割り当ては作品ごとの`drafts`へ保存します。
- UTF-8のTXTは空行ごとにシーンを分割して読み込めます。画像一括追加にも対応しています。
- シーン一覧は話者・ボイスの有無・背景・BGMで絞り込めます。元のシーン番号と再生順は変わりません。大量シーンは仮想スクロールします。
- 話者・ナレーションごとの文字色をシナリオ全体で設定でき、シーン一覧と一括作成の色分けにも反映します。UIのダーク／ライトテーマは、上部の歯車から開く設定画面で選びます。作品とは別のアプリ設定です。

再生中はクリック・Enter・Space・右矢印で次へ、左矢印で前へ。長文は固定サイズのテキスト枠でページ送りします。文字送り演出中は最初の操作で全文表示します。背景が変わると1秒でクロスフェードし、同じ画像の引き継ぎでは演出を繰り返しません。

通常は本文を中心に表示します。右クリック・Mキー・右下の「…」から再生メニューを開き、シーン番号・ページ数・前後移動・音量・全画面・終了を操作します。右下のボイス再生アイコンは常時同じ位置に表示し、ボイスがないシーンでは無効表示になります。

全画面は16:9を保って最大サイズへ拡大します。Escapeはメニューを開いていれば閉じ、全画面なら解除し、通常表示では編集画面へ戻ります。シナリオの末尾では最初から再生できます。

## 実装と検証

- `electron/main.ts`: ウィンドウ、限定IPC、専用プロトコル、OSダイアログ、終了時の保存待ち
- `electron/preload.cts`: contextBridgeによる許可APIのみの公開
- `electron/project-store.ts`: フォルダ保存、素材取り込み、直列化、バックアップ、復旧、複製
- `electron/validation.ts`: フォルダ形式・素材参照・シーンIDの検証
- `shared/desktop.ts`: Main/Preload/RendererのAPI型
- `src/desktop.ts`, `src/storage.ts`: Renderer側の保存・終了待ち・ネイティブファイル操作
- `src/assets.ts`, `src/projectPackage.ts`: 素材ID、旧JSONとZIPの互換処理
- `src/ProjectActions.tsx`: 保存・再試行・バックアップ・復旧・保存先を開くUI
- 既存の編集、一覧、一括作成、再生コンポーネントを再利用しています。

```sh
node tests/desktop.mjs        # 新規編集・下書き・音声・終了直前の保存・再起動
node tests/desktop-compat.mjs # 旧JSON/ZIP、素材重複排除、複製、移動、保存先変更
node tests/desktop-settings.mjs # 歯車設定、UserData既定、テーマ、保存先、復元・エラー
node tests/installer-userdata.mjs # NSIS削除フックで作品フォルダが残ることを確認
```

Electronテストは専用の`.desktop-test-*`フォルダと専用userDataを使い、実作品を変更しません。`npm test`は保存順序、書き込み失敗、JSON破損、素材欠損、フォルダ移動、下書き、バックアップ、パス検証も確認します。以前のブラウザ専用E2Eスクリプトは旧版向けに残していますが、現行の起動・永続化テストには上記のElectronテストを使用してください。

Main/Preloadは`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`です。Rendererに任意のIPC・fs・shell実行を公開しません。素材は開いた作品の検証済みIDだけを`tsuzuri-media://`で提供し、親ディレクトリ参照や作品外へのシンボリックリンクを拒否します。アプリ本体は`tsuzuri-app://`から読み込み、外部ナビゲーションと新規ウィンドウを禁止します。

実装時に参照した公式資料: [Electron IPC](https://www.electronjs.org/docs/latest/tutorial/ipc)、[Electron protocol](https://www.electronjs.org/docs/latest/api/protocol)、[Electron Builder NSIS](https://www.electron.build/docs/nsis/)。

## 制限

- インストーラーは未署名です。コード署名証明書と自動更新配信は含みません。
- JSONの互換書き出しは仕様上Base64を生成します。JSON/ZIPのインポート・エクスポートは処理中にアーカイブ分のメモリを使います。通常の作品読み込み・編集・再生では素材全体をBase64化・常駐展開しません。
- 大規模な作品の移動・共有はフォルダ全体のコピーが最もメモリを使いません。既存ZIPの展開上限512MB、1素材25MBは維持しています。
- マシンごとのWindowsインストール先・OneDrive・ウイルス対策ソフトによる制約は実環境で確認してください。
